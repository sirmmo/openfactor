OpenFactor

An open source factory-building platform for the browser. The simulation is a deterministic Rust library, and the game is content that runs on top of it.

Play the sandbox API reference Source on GitHub

Status

Early prototype. The core simulation and a single-player sandbox work. There is no multiplayer or public API yet, and saves are not implemented, so reloading the page starts over.

The one rule

state(t+1) = sim(state(t), commands(t))

The simulation has no clock, no I/O, no floats and no randomised containers. Anything unpredictable enters as a command. Co-op sync, replays and integrations are all planned around this rule. Every run of the same commands produces the same state hash, which the sandbox shows in its top bar.

How the base pack works

BuildingBehaviour
MinerMust sit on ore. Outputs through its front.
BeltMoves items toward its front. Several belts or machines feeding one tile take turns.
Smelter1 ore → 1 plate, 30 ticks. Takes input from anything feeding it and outputs through its front.
Assembler2 plates → 1 widget, 60 ticks.
DepotStores anything delivered to it.

The simulation runs at 60 ticks per second. A tile is 256 position units long and belt items sit at least 64 units apart. At the example speed of 16 units per tick, a belt carries one item every 4 ticks.

Rules

Everything except belts is defined in a rule pack, written in the rule language of GlassBox, the engine behind SimCity (2013). OpenFactor follows the syntax used by citysim's .gbx scripts. The sandbox's toolbar, counters and sprites all come from the base pack.

resource ore    name "Ore"    sprite 97
resource plate  name "Plates" sprite 107
layer oreField  sprites 3 32

unit miner   name "Miner"   sprite 110 placeOn oreField
unit smelter name "Smelter" sprite 75
unit depot   name "Depot"   sprite 58  stores any

unitRule mine
    appliesTo miner
    rate 30
    map oreField in 1
    local ore out 1
end

patch oreField at 0 0 size 6 6 amount 100000
place miner 2 2 east

A unit runs the first of its rules that can start. Inputs are taken at the start and outputs given rate ticks later. It accepts what its rules take, up to twice the amount, and sends what they make through its front.

Rule statementMeaning
appliesTo <unit>The unit this rule belongs to. Defaults to the rule's name.
rate <n>Ticks from start to finish. Defaults to 1.
local <R> in|out <n>, or <R> in|out <n>Items taken from or made in the unit.
global <R> in|out <n>Taken from or added to a world-wide stock.
map <M> in <n>Taken from the layer at the unit's tile.
map <M> out <n> [radius <r>]Added to the layer around the unit.
map <M> atLeast|atMost|greater|less|is <n>The rule starts only when this holds at the unit's tile. test map … also works.

Where it differs from GlassBox and citysim: numbers are whole, rules fire at the end of their rate instead of being averaged per tick, and every resource, layer and unit must be declared, so a typo is reported with its line number. Declarations are on one line in the pack itself. mapRule, zoneRule, agentRule, agent, log and options are not supported yet and are reported as errors.

Rule changes alter the state hash, so players on different rules are detected as out of sync. Names and sprites don't.

Embedding the simulation

The openfactor-sim crate has no dependencies.

use openfactor_sim::*;

let pack = Pack::parse(include_str!("base.gbx"))?;
let mut world = World::new(&pack);

world.step(&pack.worldgen.starter);
println!("{:016x}", world.state_hash());

Building from source

cargo test --workspace
rustup target add wasm32-unknown-unknown
cargo build --profile wasm --target wasm32-unknown-unknown -p openfactor-client-wasm
cp target/wasm32-unknown-unknown/wasm/openfactor_client.wasm site/play/openfactor.wasm
python3 -m http.server --directory site

Roadmap

  1. Headless simulation with replay tests (done).
  2. Browser client with a build and render loop (first version live).
  3. Two browsers in one world, with late join and desync detection.
  4. GlassBox-style rule packs (first version live), map rules, an in-game inspector and editor, and the external API.
  5. WASM mods, then federation between worlds.
